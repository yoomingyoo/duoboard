# MVP 범위 정의

## 대상 제품
**duoboard**

설명: 개발자 2인이 작은 프로젝트를 진행할 때, 할 일과 짧은 회고를 한 곳에서 가볍게 관리할 수 있는 초경량 협업 웹 앱.

## 문제 정의
- 해결하려는 문제:
  - 할 일이 메신저, 머릿속, 개인 메모에 흩어진다.
  - 진행 상태가 명확히 공유되지 않는다.
  - 회고를 따로 남기지 않아 다음 액션으로 이어지지 않는다.
- 누가 사용할 것인가:
  - 1차 사용자는 우리 둘
  - 이후에는 2~4명 규모의 작은 프로젝트 팀까지 확장 가능
- 왜 지금 이걸 만들고 싶은가:
  - 실제로 우리가 바로 쓸 수 있는 도구이기 때문
  - 첫 협업 제품으로 범위를 작게 잡기 좋기 때문
  - 출시 후에도 직접 사용하면서 개선하기 쉬운 주제이기 때문

## MVP 목표
이번 1차 버전의 목표는 **기능이 많은 협업 툴**이 아니라,
**둘이 실제로 1~2주 이상 써볼 수 있는 최소한의 협업 보드**를 만드는 것이다.

## 핵심 사용자 흐름
1. 사용자가 보드에 접속한다.
2. 할 일을 추가한다.
3. 담당자와 상태를 정한다.
4. 진행하면서 Todo / Doing / Done 상태를 변경한다.
5. 하루 또는 주간 단위로 짧은 회고를 남긴다.
6. 회고에서 나온 다음 액션을 다시 할 일로 등록한다.

## 핵심 기능
이번 1차 버전에 포함할 기능만 적는다.

### 1. 할 일 관리
- 할 일 추가 / 수정 / 완료
- 상태 구분: Todo / Doing / Done
- 담당자 구분: 나 / 상대
- 카드 또는 리스트 단위로 간단히 보기

### 2. 회고 작성
- 짧은 회고 작성
- 항목 예시: 잘한 점 / 아쉬운 점 / 다음 액션
- 회고 목록 조회

### 3. 보드에서 진행 상황 확인
- 현재 진행 중인 일과 완료된 일을 한 화면에서 확인
- 회고와 할 일이 완전히 분리되지 않고, 같은 흐름 안에서 보이도록 구성

## UI/UX 원칙
- 첫 화면에서 핵심 기능이 바로 보여야 한다.
- 복잡한 메뉴 구조 없이 한두 화면 안에서 대부분의 작업이 가능해야 한다.
- Jira 같은 무거운 느낌보다 가볍고 빠른 사용성을 우선한다.

## 이번 버전에서 하지 않을 것
- 다수 사용자 초대/조직 관리
- 복잡한 권한 체계
- 댓글/채팅 기능
- 파일 업로드
- 캘린더 연동
- 푸시/이메일 알림
- 모바일 앱 동시 개발
- 통계/대시보드 고도화
- 결제
- 관리자 기능 확장
- AI 추천 기능

## 제품 형태
- 1차는 **웹 앱**으로 진행
- 이유:
  - 개발/배포 속도가 빠르다.
  - 둘이 테스트하고 수정하기 쉽다.
  - 퍼블리싱 경험이 목표일 때 가장 부담이 적다.

## 기술 방향 초안
- 프론트엔드: 웹 기반
- 백엔드/DB: Firebase 또는 Supabase 같은 BaaS 우선 검토
- 인증:
  - 가능하면 초기에 최대한 단순하게 시작
  - 필요하면 초대 코드 또는 고정 사용자 2명 수준으로 제한

## 로그인 정책 초안
우선순위는 아래와 같다.
1. 가능하면 **로그인 없이도 데모/초기 테스트 가능한 구조**
2. 꼭 필요하면 **가벼운 로그인**만 도입
3. OAuth, 권한 고도화 등은 MVP 이후로 미룸

## 릴리즈 기준
아래 기준을 만족하면 1차 출시 가능으로 본다.
- 핵심 사용자 흐름이 끝까지 동작한다.
- 할 일 생성/상태 변경/회고 작성이 모두 가능하다.
- 치명적 오류 없이 배포 가능하다.
- 최소한의 소개 문구/스크린샷/설명이 준비된다.
- 우리 둘이 실제로 며칠간 써보고 큰 불편 없이 운영 가능하다.

## 출시 전 체크 포인트
- 보드 진입이 쉬운가?
- 할 일 등록이 10초 안에 가능한가?
- 회고 입력이 부담스럽지 않은가?
- 할 일과 회고가 자연스럽게 이어지는가?
- 첫 버전으로서 범위가 과하지 않은가?

## MVP 이후 확장 후보
- 회고 템플릿 커스터마이즈
- 주간 회고 요약 보기
- 간단한 알림
- 모바일 최적화
- PWA 또는 앱 전환 검토
- 2인 이상 소규모 팀 확장

## 미정 항목
- 회고 단위를 일간으로 할지 주간으로 할지
- 보드 UI를 칸반형으로 할지 리스트형으로 할지
- Firebase와 Supabase 중 무엇을 쓸지
- 로그인 없이 시작할지, 최소 로그인만 둘지
- 배포 채널

## 현재 권장 결정
현 시점에서는 아래처럼 가는 것이 가장 무난하다.
- 플랫폼: 웹 앱
- 보드 형태: 칸반형
- 회고 단위: 주간 회고 우선
- 백엔드: BaaS 활용
- 목표: 2주 안에 첫 화면 + 할 일 추가/이동까지 보이기
