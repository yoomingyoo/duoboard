# 아이템 정리

## 선정 아이템
**duoboard**

설명: 2인 회고/할 일 보드

둘이 함께 사용하는 아주 작은 협업 도구를 만들어, 실제 사용과 출시 경험을 동시에 얻는 것을 목표로 한다.

## 이 아이템을 고른 이유
- 둘이 직접 사용자이므로 피드백이 빠르다.
- 협업 도구 자체라 프로젝트 진행 중에도 바로 써볼 수 있다.
- 기능 범위를 작게 잡기 쉽다.
- 웹 앱으로 시작하면 비교적 빠르게 MVP를 만들고 배포할 수 있다.
- 문서화, 일정 관리, 회고, 할 일 관리 같은 실제 협업 요소와 잘 맞는다.

## 한 줄 설명
둘이 함께 할 일을 관리하고, 짧은 회고를 남기며, 진행 상황을 가볍게 공유할 수 있는 초경량 협업 보드.

## 해결하려는 문제
개발자 둘이 작은 프로젝트를 진행할 때,
- 할 일은 메신저에 흩어지고
- 회고는 따로 남기지 않게 되고
- 진행 상황이 머릿속에만 남는 경우가 많다.

이 앱은 이런 상황에서 **아주 가볍게 할 일과 회고를 함께 관리할 수 있는 공간**을 제공하는 것을 목표로 한다.

## 예상 사용자
### 1차 사용자
- 우리 둘

### 이후 확장 가능 사용자
- 2~4명 규모의 소규모 프로젝트 팀
- 스터디/사이드프로젝트 팀
- 커플/친구 단위의 간단한 공동 계획 사용자

## 핵심 가치
- 복잡하지 않다.
- 둘이 쓰기에 딱 맞는 가벼운 구조다.
- 실제 프로젝트 운영에 바로 적용 가능하다.
- 출시 후에도 직접 써보며 개선하기 쉽다.

## MVP에서 넣고 싶은 핵심 기능
### 1. 할 일 관리
- 할 일 추가 / 수정 / 완료
- 상태 구분: Todo / Doing / Done
- 담당자 구분(나 / 상대)

### 2. 짧은 회고 작성
- 하루 또는 주간 단위로 짧게 회고 작성
- 예: 잘한 점 / 아쉬운 점 / 다음 액션

### 3. 보드 형태로 진행 상황 보기
- 현재 진행 중인 일과 완료된 일을 한 화면에서 확인
- 너무 복잡한 프로젝트 관리 툴이 아니라, 가볍게 보는 수준

## MVP에서 제외할 것
- 다수 사용자 초대/조직 관리
- 복잡한 권한 체계
- 댓글/채팅 기능
- 파일 업로드
- 알림 시스템 고도화
- 캘린더 연동
- 모바일 앱 동시 개발

## 제품 형태 제안
### 1차 형태
- **웹 앱**
- 이유: 가장 빠르게 개발/배포/수정 가능

### 추후 확장 가능성
- 반응이 좋으면 PWA 또는 모바일 앱으로 확장 검토

## 차별점 아이디어
이 앱의 강점은 “기능이 많다”가 아니라,
**2인이 함께 쓰기 딱 좋은 작고 명확한 협업 도구**라는 점에 있다.

예를 들어,
- Jira처럼 무겁지 않고
- Trello처럼 범용적이기만 하지 않고
- “둘이 작은 프로젝트를 굴릴 때 필요한 최소 기능”에 집중한다.

## 실제 사용 시나리오
### 시나리오 1
- 할 일 하나를 등록한다.
- 담당자를 정한다.
- 진행 상태를 바꾼다.
- 완료 후 Done으로 옮긴다.

### 시나리오 2
- 한 주가 끝나면 각자 짧은 회고를 남긴다.
- 다음 주 액션 아이템을 다시 할 일로 등록한다.

## MVP 성공 기준
- 둘이 실제로 1~2주 이상 사용해볼 수 있다.
- 할 일 관리와 회고 작성의 기본 흐름이 문제 없이 동작한다.
- 외부에 배포 가능한 수준의 최소 UI/UX를 갖춘다.
- 출시 후 피드백을 바탕으로 1회 이상 개선 배포한다.

## 남은 결정 사항
- 로그인 필요 여부
- 회고 단위를 일간으로 할지 주간으로 할지
- 보드 UI를 칸반형으로 할지 리스트형으로 할지
- 백엔드/DB를 직접 둘지 Firebase/Supabase를 쓸지
