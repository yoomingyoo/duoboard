# duoboard

동료 개발자 2인이 함께 **작은 제품을 실제로 출시해보는 경험**을 쌓기 위한 협업용 시작 레포입니다.

## 이 레포의 목적
- 협업을 통해 실제 제품 출시 과정을 끝까지 경험한다.
- 처음부터 수익을 기대하기보다 **MVP 출시 + 운영 경험**을 우선한다.
- 웹 앱 또는 안드로이드 앱 중 하나를 선택해 1차 버전을 공개한다.

## 현재 단계
- 1차 아이템은 **2인 회고/할 일 보드**로 좁혔다.
- 이제 MVP 범위, 역할 분담, 일정, 출시 체크리스트를 구체화한다.
- 문서는 Markdown으로 관리하고, 작업은 GitHub Issue/Project로 확장한다.

## 기본 원칙
1. 작게 시작한다.
2. 핵심 기능 1~3개만 담은 MVP를 먼저 만든다.
3. 출시 경험 자체를 우선한다.
4. 기술적 멋보다 빠른 실행과 협업 경험을 중시한다.
5. 논의만 길어지지 않도록 6~8주 안에 1차 공개를 목표로 한다.

## 문서 구조
- `docs/current-status.md` : 동료/동료 AI 전달용 현재 상태 요약
- `docs/00-goal.md` : 프로젝트 목적과 성공 기준
- `docs/01-ideas.md` : 선택된 아이템의 배경과 상세 정리
- `docs/02-mvp-scope.md` : MVP 범위 정의
- `docs/03-role-and-rules.md` : 역할 분담과 협업 규칙
- `docs/04-release-checklist.md` : 출시 준비 체크리스트

## 운영 방식 제안
- 문서 정리: Markdown
- 할 일 관리: GitHub Issues
- 진행 보드: GitHub Projects
- 코드 리뷰: Pull Request

## 추천 사용 흐름
1. 동료나 동료 AI는 먼저 `docs/current-status.md`를 읽는다.
2. 이후 `docs/02-mvp-scope.md`에서 MVP 범위를 확인한다.
3. 필요하면 `docs/01-ideas.md`에서 배경과 의도를 본다.
4. 실제 개발이 시작되면 Issue/PR 중심으로 전환한다.

## 메모
이 레포는 초기에 문서/기획 중심으로 시작하고, 필요하면 그대로 실제 개발 레포로 확장하거나 별도 앱 레포를 분리할 수 있다.
