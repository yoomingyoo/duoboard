# 역할 분담 및 협업 규칙

## 역할

### 혜진 (기획 / PM / QA)
- 미정 항목 최종 결정: 로그인 정책, 회고 단위, 보드 UI, DB, 배포 채널 등
- 화면 흐름·문구·UX 디테일 정의 (본 문서 및 관련 docs 지속 갱신)
- 완성된 기능 실사용 테스트 + 버그/누락 리포트
  - "완료"라는 보고만으로 판단하지 않고 실제로 눌러보고 확인 후 승인
- 출시 후 지인 공유, 피드백 취합
- 기술적으로 어느 쪽이 더 간단한지/빠른지/범위가 적절한지 판단이 어려울 때는
  동료 AI(Claude)와 먼저 상의해서 방향을 잡은 뒤 결정한다.

### 민규 (개발)
- 기술 스택 세팅, 프론트엔드/백엔드 구현
- AI 코딩 도구(Claude Code 등) 활용해 개발 속도 확보
- PR 단위로 작업 쪼개서 진행

## 공통
- 주 1회 짧게 진행 상황 체크
- 결정 사항은 말로만 하지 말고 문서(docs/) 또는 Issue에 기록

## 협업 규칙
아래는 코드 작업 기준 규칙이다. 문서(docs/) 수정은 이 규칙 없이 바로 커밋 가능하며,
수정 후 상대에게 간단히 알리는 것으로 충분하다.

1. 큰 작업은 시작 전에 작은 단위로 나눠서 정리한다 (한 번에 몰아서 하지 않기)
2. 민규는 작업할 때 원본 코드는 그대로 두고 별도 작업본(브랜치)에서 진행한다
   (실수해도 원래대로 되돌릴 수 있게)
3. 완성된 작업은 바로 반영하지 않고, 혜진이 확인한 뒤에 합친다 (PR)
4. 한 번에 너무 많이 바꾸지 않고 조금씩 나눠서 진행한다
5. 일주일에 한 번 짧게 "어디까지 됐는지" 서로 맞춰본다

## 의사결정 원칙
- 더 멋진 것보다 더 빨리 출시 가능한 것을 고른다.
- 필요 이상으로 복잡한 기술 도입을 피한다.
- 의견이 갈리면 MVP에 더 유리한 쪽을 우선한다.

## 커뮤니케이션
- 결정 사항은 문서 또는 이슈에 남긴다.
- 말로만 합의하고 기록하지 않는 상황을 줄인다.
