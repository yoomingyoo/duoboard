# Current Status

이 문서는 **동료 개발자 또는 동료 AI 에이전트가 현재 프로젝트 상태를 빠르게 파악하기 위한 handoff 문서**입니다.
긴 문서를 모두 읽기 전에 이 문서를 먼저 보면 현재 맥락을 빠르게 이해할 수 있습니다.

## 프로젝트 목적
동료 개발자 2인이 함께 작은 제품을 실제로 출시해보며,
아이템 선정 → MVP 정의 → 개발 → 배포 → 피드백 반영까지의 전체 협업 사이클을 경험하는 것이 목적이다.

- 수익화가 1차 목표는 아님
- 실제 출시 경험과 협업 경험이 우선
- 범위를 작게 잡고 끝까지 가는 것이 중요

## 현재 확정된 사항
### 1. 프로젝트 아이템
- **duoboard**
- 설명: 2인 회고/할 일 보드

### 2. 제품 형태
- **웹 앱 우선**

### 3. 제품 한 줄 설명
- 둘이 함께 할 일을 관리하고, 짧은 회고를 남기며, 진행 상황을 가볍게 공유할 수 있는 초경량 협업 보드

### 4. 현재 MVP 핵심 방향
- 할 일 관리
- 회고 작성
- 한 화면에서 진행 상황 확인

## 왜 이 아이템을 골랐는가
- 둘이 직접 사용자이므로 피드백이 빠르다.
- 프로젝트를 진행하면서 실제로 바로 써볼 수 있다.
- 기능 범위를 작게 잡기 쉽다.
- 첫 출시 프로젝트로 적합할 만큼 구현 복잡도를 통제하기 쉽다.

## 현재 단계 요약
현재는 **아이템 선정 완료 / MVP 범위 구체화 단계**이다.
아직 실제 개발은 시작하지 않았고, 먼저 아래를 정리하려는 상태다.

- MVP 핵심 기능 최종 확정
- 역할 분담
- 기술 스택 초안
- 6~8주 일정 초안

## 현재 권장 방향
현 시점에서 가장 무난한 방향은 아래와 같다.

- 플랫폼: 웹 앱
- UI 형태: 칸반형 보드 우선 검토
- 회고 단위: 주간 회고 우선 검토
- 백엔드/DB: Firebase 또는 Supabase 같은 BaaS 우선 검토
- 목표: 2주 안에 첫 화면 + 할 일 추가/상태 이동까지 구현 가능한 수준으로 시작

## 아직 미정인 사항
- 로그인 없이 시작할지, 최소 로그인만 둘지
- 회고 단위를 일간으로 할지 주간으로 할지
- 보드 UI를 칸반형으로 할지 리스트형으로 할지
- Firebase와 Supabase 중 무엇을 쓸지
- 실제 배포 채널

## 이 프로젝트에서 중요하게 보는 점
- 기능을 많이 넣는 것보다 실제로 끝까지 출시하는 것
- 무거운 협업 툴이 아니라 가벼운 2인용 도구로 시작하는 것
- 우리가 직접 사용자로서 써보며 빠르게 개선할 수 있는 구조

## 동료 AI가 이해해야 하는 핵심 맥락
1. 이 프로젝트는 아이디어 탐색보다는 **출시 경험 확보**가 목적이다.
2. 범위를 작게 유지하는 것이 매우 중요하다.
3. 현재 아이템은 이미 **2인 회고/할 일 보드**로 좁혀져 있다.
4. 지금 필요한 것은 새로운 아이디어 제안보다 **MVP 구체화와 실행 계획 정리**에 가깝다.

## 다음에 기대하는 액션
동료 또는 동료 AI가 다음 중 하나를 도와줄 수 있다.

1. MVP 핵심 기능 3개를 더 날카롭게 줄이기
2. 역할 분담안 제안
3. 기술 스택 초안 제안
4. 6~8주 개발/출시 일정 초안 제안
5. 실제 구현 시작용 초기 구조 제안
