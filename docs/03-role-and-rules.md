# 역할 분담 및 협업 규칙

## 역할

### 혜진 (기획 / PM / QA)
- 미정 항목 5개 최종 결정: 로그인 정책, 회고 단위, 보드 UI, DB, 배포 채널
- 화면 흐름·문구·UX 디테일 정의 (본 문서 및 관련 docs 지속 갱신)
- 완성된 기능 실사용 테스트 + 버그/누락 리포트
  - "완료"라는 보고만으로 판단하지 않고 실제로 눌러보고 확인 후 승인
- 출시 후 지인 공유, 피드백 취합

### 민규 (개발)
- 기술 스택 세팅, 프론트엔드/백엔드 구현
- AI 코딩 도구(Claude Code 등) 활용해 개발 속도 확보
- PR 단위로 작업 쪼개서 진행

## 공통
- 주 1회 짧게 진행 상황 체크
- 결정 사항은 말로만 하지 말고 문서(docs/) 또는 Issue에 기록

## 협업 규칙
1. 큰 기능은 시작 전에 이슈로 쪼갠다.
2. 작업은 기능 브랜치에서 진행한다.
3. 바로 main에 푸시하지 않고 PR 기반으로 합친다.
4. PR은 작게 나눈다.
5. 매주 1회 짧게 진행 상황을 맞춘다.

## 의사결정 원칙
- 더 멋진 것보다 더 빨리 출시 가능한 것을 고른다. // 더 멋진거 고르고 싶어 ㅠ
- 필요 이상으로 복잡한 기술 도입을 피한다.
- 의견이 갈리면 MVP에 더 유리한 쪽을 우선한다.

## 커뮤니케이션
- 결정 사항은 문서 또는 이슈에 남긴다.
- 말로만 합의하고 기록하지 않는 상황을 줄인다.
